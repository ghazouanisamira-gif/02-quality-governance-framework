# KPI Governance Framework — Example

> **Demonstration / Fictional Data — not a real quality report.**

## Purpose

Demonstrate how a KPI becomes a governed management instrument rather than a number displayed on a dashboard.

## KPI Definition

**KPI:** Quality Compliance Rate

**Definition:** Percentage of evaluated interactions meeting the defined quality criteria.

**Formula:** Compliant evaluations ÷ Total valid evaluations × 100

## Governance Structure

| Element | Definition |
|---|---|
| Owner | Quality Manager |
| Data source | Quality evaluation system |
| Frequency | Weekly |
| Review | Weekly operational review |
| Threshold | ≥90% |
| Escalation | <85% or sustained deterioration |
| Action owner | Relevant operations manager |

## Example Trend

| Week | Result | Status | Management Interpretation |
|---|---:|---|---|
| W1 | 91% | Stable | Maintain |
| W2 | 89% | Watch | Analyse variation |
| W3 | 84% | Action | Root-cause analysis |
| W4 | 87% | Recovery | Monitor corrective action |
| W5 | 92% | Sustained | Standardize / sustain |

## Closed-Loop Management

**Measure → Validate → Analyse → Diagnose → Act → Verify → Sustain**

A KPI should trigger a management decision when its defined threshold or trend rule is reached.

## Root-Cause Questions

- Is the issue capability-related?
- Is the process unclear or inconsistent?
- Are tools or information creating friction?
- Is workload affecting execution?
- Is the measurement itself reliable?
- Is governance / ownership unclear?

## Corrective Action Example

**Signal:** quality falls below threshold.

**Diagnosis:** fictional analysis identifies inconsistent application of one process step.

**Action:** clarify the procedure, issue a job aid, coach affected roles and verify application through the next evaluation cycle.

> All data and scenarios are fictional.
